Реализация функций на C и модульное тестирование с ведением проекта в Git

1. Цель работы

В этой работе необходимо реализовать набор функций на языке C, покрыть их модульными тестами с использованием библиотеки CUnit и вести разработку в Git. Контролируются две составляющие:

  • Техническая — функции работают по спецификации, тесты проходят, код собирается без ошибок и предупреждений.
  • Инженерная (Git) — каждая задача оформлена как отдельная ветка, история коммитов осмысленна, слияния выполнены в main, репозиторий в момент сдачи находится в чистом состоянии.

Основной результат — работающие функции на C и проходящие модульные тесты CUnit. Проект должен собираться без ошибок и предупреждений.

2. Что сдаётся

На проверку предоставляется:

  1. Архив с полной папкой проекта, включая скрытую .git/. Без папки .git/ история отсутствует, и работа принимается по нижней границе оценки.
  2. Отчет в корне репозитория, содержащий:
    • список выполненных задач (номера);
    • вывод команды git log --oneline --graph --all, вставленный как блок кода;
    • для задач 18 и 19 (если выбраны) — ссылку на отдельный репозиторий;
    • листинг.
    • Демонстрация прохождения тестов. Скриншот, запуска make test (или вашей команды сборки тестов), где видно, что все тесты проходят.

3. Структура репозитория

В корне репозитория должны находиться следующие файлы:

ФайлНазначение
main.c Точка входа программы. Содержит main() с демонстрационными вызовами реализованных функций.
func.h Объявления всех функций func_1 … func_17, а также общие #include.
func.c Реализации всех функций. Одна задача — одна функция.
test_main.c Функция main() для запуска тестов CUnit.
test_func.c, test_func.h Опционально. Если хотите разнести тесты по файлам — можно.
Makefile Сборка основной программы и тестов. Цели all, test, clean.
.gitignore Исключения из репозитория (см. раздел 4.1).

Готовый Makefile для основного проекта

Чтобы не тратить время на настройку сборки, скопируйте этот шаблон в файл Makefile в корне репозитория. Он рассчитан на файлы main.c, func.c, func.h и test_main.c. Для задания 18 или 19, которое выполняется в отдельном репозитории, имена исходников в Makefile нужно согласовать с файлами выбранной игры. 

CC ?= cc
CFLAGS ?= -std=c11 -Wall -Wextra -Wpedantic -O2
CPPFLAGS ?=
LDFLAGS ?=
LDLIBS ?=
CUNIT_LIBS ?= -lcunit

.PHONY: all test clean

# Собрать основную программу.
all: main

main: main.o func.o
	$(CC) $(LDFLAGS) -o $@ $^ $(LDLIBS)

# Собрать тесты и запустить их.
test: test_main
	./test_main

test_main: test_main.o func.o
	$(CC) $(LDFLAGS) -o $@ $^ $(CUNIT_LIBS) $(LDLIBS)

# Общее правило компиляции исходников в объектные файлы.
%.o: %.c
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

# Зависимости от заголовков: при их изменении нужные файлы пересоберутся.
main.o: main.c func.h
func.o: func.c func.h
test_main.o: test_main.c func.h

clean:
	rm -f *.o main test_main

Основные команды:

  • make — собрать основную программу main;
  • make test — собрать тесты и запустить их;
  • make clean — удалить объектные файлы и собранные программы.

Для выполнения make test в системе должна быть установлена библиотека CUnit. Если библиотека установлена нестандартно, значение CUNIT_LIBS можно переопределить при запуске make.

Задачи 18 и 19 оформляются в отдельных репозиториях с собственной структурой (см. описание этих задач).

4. Правила работы с Git

4.1. Файл .gitignore

В корне репозитория должен быть .gitignore, исключающий артефакты сборки и системный мусор. Рекомендуемое содержимое: 

# артефакты сборки
*.o
*.obj
*.exe

# скомпилированные бинарники
main
test_main
test_runner

# покрытие (если включите)
*.gcda
*.gcno
*.gcov

# редакторы
.vscode/
.idea/
*.swp

# система
.DS_Store
Thumbs.db

# логи
*.log

Проверка: после сборки проекта (make) команда git status должна оставаться чистой. Если в статусе появились *.o или main — .gitignore неполный.

4.2. Базовый workflow (обязателен для каждой задачи 1–17)

Каждая задача из списка 1–17 выполняется по одному и тому же сценарию. Он не повторяется в описании отдельных задач — подразумевается по умолчанию.

  1. Убедиться, что вы на main и репозиторий чистый: 
    $ git switch main
$ git status
On branch main
nothing to commit, working tree clean
  2. Создать ветку под задачу feature/func-NN, где NN — двузначный номер задачи (01, 02, … 17): 
    $ git switch -c feature/func-07
  3. Реализовать функцию в func.c, объявление — в func.h, тесты — в test_main.c.
  4. Сделать минимум 2 коммита на ветке:
    • первый — реализация функции;
    • второй — тесты к ней.
    Пример: 
    $ git add func.c func.h
$ git commit -m "feat: implement func_07 (index of value)"
$ git add test_main.c
$ git commit -m "test: add tests for func_07"
  5. Убедиться, что тесты проходят, затем слить ветку в main с флагом --no-ff — это создаёт отдельный merge-коммит, и история остаётся читаемой: 
    $ git switch main
$ git merge --no-ff feature/func-07 -m "Merge branch 'feature/func-07'"
Почему --no-ff

Без этого флага Git при возможности делает fast-forward — и в истории не видно, что была отдельная ветка. С --no-ff создаётся merge-коммит, и по git log --graph сразу понятно, какие задачи выполнялись в отдельных ветках. Это часть требований.

4.3. Соглашение о сообщениях коммитов

Сообщение коммита имеет вид <тип>: <краткое описание>. Тип — одно из:

ТипКогда использоватьПример
initПервичная настройка репозиторияinit: setup project structure and CUnit
featРеализация функцииfeat: implement func_05 (min in array)
testДобавление или правка тестовtest: add tests for func_05
fixИсправление ошибки в уже закоммиченном кодеfix: handle empty array in func_02
docsДокументацияdocs: add build instructions to README
choreСлужебные изменения (сборка, .gitignore)chore: add .gitignore for build artifacts

4.4. Соглашение об именах веток

  • main — стабильная ветка. Только merge из feature/*.
  • feature/func-NN — одна задача. Например: feature/func-01, feature/func-17.
  • После merge — удаляется.

4.5. Общие требования к истории

  • Коммиты атомарные: один коммит — одно логическое изменение.
  • Никаких сообщений вида fix, update, WIP, asdf.
  • В main не должно быть незакоммиченных изменений к моменту сдачи.
  • Все ветки, кроме main, удалены после слияния.

5. Список заданий

Для каждой задачи указаны прототип функции и её поведение. Задания 1–17 реализуются в файле func.c; объявления функций размещаются в func.h. Имена функций имеют формат func_N(), где N — номер задания.

01

Максимум из трёх чисел

Прототип
int func_1(int a, int b, int c);
Описание
Возвращает наибольшее из трёх целых чисел.
02

Произведение чётных элементов массива

Прототип
long func_2(int arr[], int size);
Описание
Принимает массив целых и его размер. Возвращает произведение всех чётных элементов. Если в массиве нет чётных элементов — функция возвращает 1 (по правилу пустого произведения).
03

Произведение нечётных элементов массива

Прототип
long func_3(int arr[], int size);
Описание
Аналогично func_2, но для нечётных элементов. Если нечётных нет — возвращает 1.
04

Максимум в массиве

Прототип
int func_4(int arr[], int size);
Описание
Возвращает максимальный элемент массива. Поведение при size == 0 — на ваш выбор; задокументируйте в комментарии.
05

Минимум в массиве

Прототип
int func_5(int arr[], int size);
Описание
Возвращает минимальный элемент массива.
06

Среднее значение в массиве

Прототип
double func_6(int arr[], int size);
Описание
Возвращает среднее арифметическое элементов массива. При size == 0 верните 0.0.
07

Поиск индекса значения в массиве

Прототип
int func_7(int arr[], int size, int v);
Описание
Возвращает индекс первого вхождения v в массив или -1, если значения нет. Пример: [1,2,3,4,5,6], size=6, v=3 → 2.
08

Количество элементов, равных заданному

Прототип
int func_8(int arr[], int size, int a);
Описание
Возвращает, сколько раз число a встречается в массиве.
09

Количество элементов, больших заданного

Прототип
int func_9(int arr[], int size, int a);
Описание
Возвращает количество элементов массива, строго больших a.
10

Обрезка пробелов в начале и конце строки

Прототип
char *func_10(char *s);
Описание
Удаляет пробельные символы (' ', '\t', '\n') в начале и конце строки. Пример: " Hello " → "Hello". Можно модифицировать на месте или вернуть новый буфер — задокументируйте в комментарии.
11

Сдвиг массива влево на k позиций

Прототип
void func_11(int arr[], int size, int k);
Описание
Циклически сдвигает массив на k позиций влево. Пример: [1,2,3,4,5], k=2 → [3,4,5,1,2]. Корректно обработать k > size.
12

Переворот строки

Прототип
void func_12(char *s);
Описание
Переворачивает строку на месте. Пример: "hello" → "olleh".
13

Удаление всех пробелов из строки

Прототип
void func_13(char *s);
Описание
Удаляет все пробельные символы из строки. Пример: "Hello world" → "Helloworld".
14

Проверка возможности треугольника

Прототип
int func_14(int a, int b, int c);
Описание
Возвращает 1, если из трёх отрезков можно составить треугольник, иначе 0. Правило: если одна сторона больше или равна сумме двух других — треугольник невозможен. Пример: (3,4,5) → 1; (1,2,3) → 0.
15

Заглавная первая буква слова

Прототип
char *func_15(char *s);
Описание
Меняет первую букву на заглавную, остальные символы не трогает. Пример: "summer" → "Summer"; "SuMmer" → "SuMmer"; "caT" → "CaT".
16

Сокращение длинных слов (abbreviation)

Прототип
char *func_16(const char *word);
Описание
Если длина слова строго больше 10, вернуть аббревиатуру вида первая_буква + (длина − 2) + последняя_буква. Иначе вернуть слово как есть. Примеры: localization → l10n; internationalization → i18n; word → word.
17

Стоимость доставки интернет-магазина

Прототип
int func_17(int count);
Описание
Принимает количество товаров в заказе и возвращает стоимость доставки: 780 руб. за первый товар и 210 руб. за каждый последующий. Пример: count = 1 → 780; count = 4 → 780 + 3·210 = 1410. Обработать count ≤ 0 — вернуть 0.

5.2. Задания 18–19 — отдельные проекты

Задания 18 и 19 оформляются каждое в своём репозитории. Структура проекта и история Git строятся по тем же правилам (раздел 4), но появляются дополнительные требования: полноценный Makefile с зависимостями и отдельная история разработки.

18

Игра «Быки и коровы»

Функции
  • Генерация секретного кода — void generate_secret(char *secret, int length);
  • Подсчёт быков и коров — void count_bulls_cows(const char *secret, const char *guess, int *bulls, int *cows);
  • Опционально: функция подсчёта попыток, функция вывода подсказки.
Тесты
Обязательно покрыть CUnit-тестами функцию count_bulls_cows: пустой ввод, полное совпадение, полное несовпадение, частичное совпадение быков и коров. Функция генерации — опционально.
Makefile
Отдельный Makefile с целями all, test, clean. Обязательно указать зависимости объектных файлов от заголовочных: 
game.o: game.c game.h
	$(CC) $(CFLAGS) -c game.c -o game.o
19

Игра «Крестики-нолики»

Функции
  • Вывод игрового поля — void print_board(char board[3][3]);
  • Проверка занятости клетки — int is_cell_free(char board[3][3], int row, int col);
  • Установка хода — int make_move(char board[3][3], int row, int col, char mark);
  • Проверка победы / ничьей — int check_game_over(char board[3][3]);
Тесты
Обязательно покрыть CUnit-тестами is_cell_free, make_move и check_game_over: горизонтальная победа, вертикальная, диагональная, ничья, пустое поле, победа не наступила.
Makefile
Отдельный Makefile с зависимостями между исходниками и заголовками. Цели all, test, clean.

Приложение A. Пример полного workflow одной задачи

Ниже — пошаговый пример для задачи 7 (поиск индекса значения). Для других задач сценарий аналогичен, меняются только имена файлов, сообщения и код. 

# 1. Убедиться, что на main и всё чисто
$ git switch main
$ git status
On branch main
nothing to commit, working tree clean

# 2. Создать ветку под задачу
$ git switch -c feature/func-07
Switched to a new branch 'feature/func-07'

# 3. Написать функцию в func.c и объявление в func.h
#    (редактор — ваш)

# 4. Сделать первый коммит — реализацию
$ git add func.c func.h
$ git commit -m "feat: implement func_07 (index of value)"
[feature/func-07 3a7c2b1] feat: implement func_07 (index of value)
 2 files changed, 18 insertions(+)

# 5. Написать тесты, проверить что проходят
$ make test
CUnit — all tests passed (8 assertions)

# 6. Второй коммит — тесты
$ git add test_main.c
$ git commit -m "test: add tests for func_07"
[feature/func-07 5e1d8f3] test: add tests for func_07
 1 file changed, 24 insertions(+)

# 7. Слить в main с --no-ff
$ git switch main
Switched to branch 'main'
$ git merge --no-ff feature/func-07 -m "Merge branch 'feature/func-07'"
Merge made by the 'ort' strategy.
 func.c      | 18 +++++++++++++++
 func.h      |  1 +
 test_main.c | 24 +++++++++++++++++++++
 3 files changed, 43 insertions(+)

# 8. Удалить ветку
$ git branch -d feature/func-07
Deleted branch feature/func-07 (was 5e1d8f3).
