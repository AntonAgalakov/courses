Практика

Минимальный проект с CUnit

Пример показывает, как отделить код программы от тестов. Функция складывает два числа, а тест проверяет результат.

ГлавнаяWindowsLinuxПростой проект

1. Структура проекта

example/
├── Makefile
├── main.c
├── func.c
├── func.h
└── test_main.c

Все файлы также находятся в папке example в комплекте. Откройте их обычным текстовым редактором.

2. Объявление функции — func.h

#ifndef FUNC_H
#define FUNC_H

int func_1(int a, int b);

#endif

Заголовок содержит прототип, чтобы функцию можно было вызывать из main.c и тестов.

3. Реализация — func.c

#include "func.h"

int func_1(int a, int b)
{
    return a + b;
}

4. Основная программа — main.c

#include <stdio.h>
#include "func.h"

int main(void)
{
    printf("2 + 3 = %d\n", func_1(2, 3));
    return 0;
}

5. Тест CUnit — test_main.c

#include <CUnit/Basic.h>
#include <stdlib.h>
#include "func.h"

static void test_func_1_adds_numbers(void)
{
    CU_ASSERT_EQUAL(func_1(2, 3), 5);
    CU_ASSERT_EQUAL(func_1(-2, 2), 0);
    CU_ASSERT_EQUAL(func_1(0, 0), 0);
}

int main(void)
{
    if (CU_initialize_registry() != CUE_SUCCESS) {
        return EXIT_FAILURE;
    }

    CU_pSuite suite = CU_add_suite("func_1 tests", NULL, NULL);
    if (suite == NULL) {
        CU_cleanup_registry();
        return EXIT_FAILURE;
    }

    if (CU_add_test(suite, "adds integers", test_func_1_adds_numbers) == NULL) {
        CU_cleanup_registry();
        return EXIT_FAILURE;
    }

    CU_basic_set_mode(CU_BRM_VERBOSE);
    CU_basic_run_tests();

    unsigned int failures = CU_get_number_of_failures();
    CU_cleanup_registry();
    return failures == 0 ? EXIT_SUCCESS : EXIT_FAILURE;
}

Тест проверяет три случая. Если результат хотя бы одной проверки отличается от ожидаемого, CUnit покажет ошибку, а программа тестов завершится с ненулевым кодом.

6. Сборка — Makefile

CC ?= cc
CFLAGS ?= -std=c11 -Wall -Wextra -Wpedantic -O2
CPPFLAGS ?=
LDFLAGS ?=
LDLIBS ?=
CUNIT_LIBS ?= -lcunit

.PHONY: all test clean

all: main

main: main.o func.o
	$(CC) $(LDFLAGS) -o $@ $^ $(LDLIBS)

test: test_main
	./test_main

test_main: test_main.o func.o
	$(CC) $(LDFLAGS) -o $@ $^ $(CUNIT_LIBS) $(LDLIBS)

%.o: %.c
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

main.o: main.c func.h
func.o: func.c func.h
test_main.o: test_main.c func.h

clean:
	rm -f *.o main test_main

В строках команд перед $(CC), ./test_main и rm в реальном файле Makefile используются символы табуляции, а не пробелы. Готовый Makefile в папке example уже содержит табуляцию.

7. Запуск

Откройте терминал в папке example и выполните:

make
./main
make test
make clean
КомандаНазначение
makeСобрать обычную программу main.
./mainЗапустить программу; ожидаемый вывод: 2 + 3 = 5.
make testСобрать и запустить модульные тесты CUnit.
make cleanУдалить объектные файлы и собранные исполняемые файлы.
Если тесты успешны, CUnit покажет ноль ошибок. Попробуйте изменить функцию или ожидаемое значение в одном из тестов, чтобы увидеть, как выглядит проваленная проверка; затем верните исходный код.

Типичные ошибки

  • Не найден заголовок CUnit/Basic.h — не установлены файлы разработки CUnit или используется другое окружение компилятора.
  • Не найдена библиотека -lcunit — проверьте установку пакета и совпадение архитектуры/окружения.
  • missing separator от Make — в строках команд Makefile должны начинаться с табуляции.
Перед использованием CUnit выполните инструкцию для своей системы: Windows или Linux.
