1. Введение

В главе 1 мы установили Git и убедились, что команда git --version выводит номер версии. С этого момента Git может выполнять команды, но ещё не готов к полноценной работе: он не знает, кто Вы, и не сможет подписать Ваш первый коммит.

Хорошая новость: для старта нужно настроить всего две вещи — имя и email. Всё остальное у Git уже имеет разумные значения по умолчанию. Редактор, имя главной ветки, обработку окончаний строк и псевдонимы можно настроить позже — когда появится реальная потребность. В этой главе мы их не трогаем, чтобы не усложнять старт.

Ещё одна хорошая новость: настройка выполняется один раз. Все настройки сохраняются в обычных текстовых файлах, Git читает их при каждом запуске и применяет автоматически. После этой главы о настройке можно забыть до тех пор, пока не понадобится что-то поменять.

2. Зачем настраивать Git

Git — инструмент, который по умолчанию работает «как есть». Но одну вещь он знать обязан: кто автор коммита. В каждый коммит Git записывает имя и email того, кто его создал. Без этих данных команда git commit просто откажется выполняться и попросит их указать.

Настройка в Git — это пара «ключ → значение». Например, user.name → «Иван Иванов», user.email → «ivan@example.com». Ключ и значение разделяются пробелом. В командах git config это выглядит так: 

$ git config --global user.name "Иван Иванов"

Здесь user.name — ключ, "Иван Иванов" — значение, а --global — уровень, на котором сохраняется настройка. Об уровнях — в следующем разделе.

Универсальный синтаксис

Все команды настройки в Git имеют общий вид: git config [уровень] <ключ> "<значение>". Уровень — --system, --global или --local. В командах настройки мы почти всегда будем использовать --global.

3. Три уровня конфигурации

Git хранит настройки в трёх разных местах. Это не случайно: уровни позволяют задать значение один раз для всех пользователей компьютера, отдельно для себя и отдельно для конкретного проекта. Пока достаточно понимать, что они существуют и какой из них использовать в каком случае.

--system
Системный уровень
Действует на всех пользователей компьютера. Трогать почти никогда не нужно.
Linux/macOS: /etc/gitconfig · Windows: C:\Program Files\Git\etc\gitconfig
--global
Пользовательский (глобальный) уровень
Действует на текущего пользователя во всех его репозиториях. Сюда попадает всё, что мы будем настраивать.
Linux/macOS: ~/.gitconfig · Windows: C:\Users\<имя>\.gitconfig
--local
Локальный уровень
Действует только в текущем репозитории. Нужен, когда проект требует особых настроек — например, другой email для рабочего репозитория.
Внутри репозитория: .git/config
Приоритет: local перекрывает global, а global перекрывает system.

Рис. 1. Три уровня конфигурации Git, где что лежит и чей приоритет выше

3.1. Какой уровень выбирать

Практически всегда используется --global — это Ваши личные настройки, они одинаковы во всех Ваших проектах. --local нужен редко, только для «особого» проекта. --system — почти никогда, оставьте его администратору компьютера.

3.2. Что будет, если задать один и тот же ключ на разных уровнях

Побеждает «более близкий к репозиторию»:

Где заданоЧто увидит Git
Только --systemЗначение из системной настройки.
--system и --globalЗначение из --global.
--system, --global и --localЗначение из --local.
Классическая ошибка

Забыть флаг --global. Команда git config user.name "..." без флага по умолчанию пишет в локальный конфиг текущего репозитория. Если Вы выполняете её вне репозитория — Git выдаст ошибку fatal: not in a git directory. Если внутри — настройка применится только к нему, а в остальных проектах имя будет считаться незаданным. Всегда проверяйте, что --global на месте, если хотите настройку «для себя везде».

4. Имя и email: обязательный минимум

В каждый коммит Git записывает, кто его сделал. Эти данные берутся из двух настроек: user.name и user.email. Без них git commit не выполнится и попросит их указать. Это единственное, что обязательно настроить, чтобы начать работать.

commit 3f2a1b7...
Author: Иван Иванов <ivan@example.com> ← из user.name и user.email
Date:   Mon Oct 20 14:32:11 2026 +0300

    Добавить приветствие в hello.txt

Рис. 2. Поля user.name и user.email попадают в каждый коммит

4.1. Как задать имя и email

Две команды, выполняются по очереди в терминале:

$ git config --global user.name "Иван Иванов"
$ git config --global user.email "ivan@example.com"

Разбор первой команды:

  • git config — команда управления настройками Git.
  • --global — уровень: текущий пользователь, все репозитории.
  • user.name — ключ. Префикс user. обозначает раздел «пользователь», name — имя настройки.
  • "Иван Иванов" — значение, в кавычках. Кавычки обязательны, если в значении есть пробелы — иначе терминал разобьёт его на два аргумента и Git выдаст ошибку.

Вторая команда устроена точно так же, только ключ — user.email, а значение — адрес электронной почты. Кавычки здесь не обязательны (в адресе нет пробелов), но привычнее всегда использовать их.

4.2. Какое имя и какой email указывать

  • Имя — любое, как Вам удобно. Оно попадёт в историю коммитов и будет видно всем, кто её смотрит. Обычно пишут реальное имя или никнейм.
  • Email — должен быть настоящим, если планируете пользоваться GitHub / GitLab. По email сервисы связывают коммиты с Вашим аккаунтом.
Важно

Значения user.name и user.email не проверяются на существование. Если опечататься в email, Git этого не заметит и запишет опечатку в коммиты. Проверяйте себя командой проверки (см. ниже).

4.3. Проверить, что настройки применились

После ввода команд полезно убедиться, что Git их запомнил. Команда git config <ключ> без значения выводит текущее значение ключа: 

$ git config --global user.name
Иван Иванов

$ git config --global user.email
ivan@example.com
Разбор команд
  • git config — команда настройки.
  • --global — смотрим именно глобальный уровень (а не «итоговое значение с учётом всех уровней»).
  • user.name — ключ, значение которого хотим увидеть.
  • Значения после ключа нет — значит, это запрос, а не установка.
Разбор вывода
Что вывел Git
Иван Иванов
Значение ключа user.name на уровне --global. Именно это имя попадёт в следующие коммиты.
ivan@example.com
Значение ключа user.email на уровне --global.

Если команда ничего не вывела — значит, настройка не сохранилась (например, была опечатка в ключе). Вернитесь к шагу 4.1 и выполните команду заново.

Совет на будущее

Когда Вы сделаете первый git commit без флага -m, Git откроет текстовый редактор для ввода сообщения коммита. По умолчанию это Vim — редактор мощный, но для новичка неудобный. Чтобы выйти из него, не сохраняя ничего, нажмите Esc, затем наберите :q! и нажмите Enter. Пока осваиваетесь — просто всегда используйте git commit -m "сообщение", тогда редактор не откроется вовсе.

4.4. Разные email для работы и личных проектов

Частая ситуация: на работе нужен корпоративный email, дома — личный. Решается локальными настройками внутри конкретного репозитория: 

# один раз глобально — личные данные
$ git config --global user.name "Иван Иванов"
$ git config --global user.email "ivan@personal.com"

# внутри рабочего репозитория — переопределяем
$ cd work-project
$ git config --local user.email "i.ivanov@company.com"

После этого в work-project коммиты будут подписаны рабочим email, а во всех остальных репозиториях — личным. Это тот самый приоритет уровней: --local перекрывает --global.

5. Изменение и удаление настроек

Настройки — это просто пары ключ-значение. Их можно менять сколько угодно раз: новая команда git config с тем же ключом просто перезапишет старое значение. Старое значение нигде не сохраняется.

5.1. Изменить значение

$ git config --global user.name "Пётр Петров"

Ключ user.name уже был — теперь его значение заменено на «Пётр Петров». Следующие коммиты будут подписаны новым именем.

5.2. Удалить настройку

$ git config --global --unset user.name
Разбор команды
  • git config — команда настройки.
  • --global — уровень, из которого удаляем.
  • --unset — флаг «удалить ключ» (в отличие от обычного поведения, когда значение устанавливается).
  • user.name — ключ, который удаляем.

После выполнения git config --global user.name уже ничего не выведет — ключ удалён. И git commit снова будет просить имя.

5.3. Посмотреть все настройки

Если хотите увидеть сразу все настройки (не только имя и email), есть команда git config --list: 

$ git config --list
diff.astextplain.textconv=astextplain
filter.lfs.clean=git-lfs clean -- %f
http.sslbackend=openssl
user.name=Иван Иванов
user.email=ivan@example.com
Разбор команды
  • --list — вывести все настройки, а не одну.
  • Выводятся настройки всех уровней, объединённые в один список.
Разбор вывода
Что вывел Git (пример)
diff.astextplain.textconv=astextplain
Служебная настройка, поставленная вместе с Git. Не трогаем.
filter.lfs.clean=git-lfs clean -- %f
Настройки Git LFS (Large File Storage) — расширения для больших файлов. Установлены вместе с Git. Не трогаем.
http.sslbackend=openssl
Библиотека для HTTPS-соединений. Служебное.
user.name=Иван Иванов
Ваше имя для подписи коммитов — то, что мы настроили.
user.email=ivan@example.com
Ваш email — тоже из наших настроек.

Список будет короче или длиннее в зависимости от версии Git и от того, что Вы уже успели настроить. Главное — найти в нём строки user.name и user.email и убедиться, что значения правильные.

Проверка после любых изменений

После изменения или удаления настройки полезно сразу проверить результат: git config --global <ключ> покажет именно тот уровень, который Вы меняли, а git config --list — всё сразу.

6. Итоги главы

Что нужно вынести из главы 2:

  • Git хранит настройки в виде пар «ключ → значение» в текстовых файлах.
  • Три уровня конфигурации: --system, --global, --local. Приоритет: local > global > system.
  • Почти все личные настройки задаются на уровне --global.
  • Обязательный минимум для начала работы: user.name и user.email. Без них git commit не выполняется.
  • Проверить настройку: git config --global <ключ>. Посмотреть всё: git config --list.
  • Изменить настройку — просто повторно вызвать git config с тем же ключом. Удалить — флаг --unset.
  • Остальные настройки (редактор, ветка по умолчанию, окончания строк, псевдонимы) можно оставить по умолчанию. К ним можно вернуться позже, когда появится потребность.
