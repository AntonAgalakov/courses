Параллельный grep
std::thread · std::mutex · std::queue

Консольная утилита, которая ищет подстроку в файлах.

1 Задание

Нужно написать консольную программу на C++17 pgrep, которая:

  1. Ищет фиксированную подстроку (не регулярное выражение) в файлах, переданных аргументами.
  2. Умеет рекурсивно обходить каталоги через std::filesystem.
  3. Умеет работать в двух режимах: последовательном и параллельном (N потоков через std::thread).
  4. Печатает совпавшие строки в формате [путь:][номер:]содержимое.
  5. Не падает из-за одного нечитаемого или битого файла — считает его ошибкой и идёт дальше.
Единица параллельной работы — файл. Файл целиком обрабатывается одним потоком и не делится между потоками. Ускорение достигается за счёт обработки множества файлов одновременно.
2 Что должна делать программа

2.1. Интерфейс командной строки

pgrep [OPTIONS] PATTERN [PATH...]

PATTERN — обязательная подстрока. PATH — файлы и/или каталоги; по умолчанию .. Имя файла печатается, если путей больше одного или включён -r.

ОпцияСемантикаПример
-rРекурсивный обход каталогов (симлинки не разыменовывать)pgrep -r foo src/ — ищет foo во всех файлах под src/
-iБез учёта регистра (ASCII)pgrep -i error log.txt найдёт Error, ERROR, error
-vИнвертировать: печатать строки без совпаденияpgrep -v foo a.txt — все строки a.txt, кроме содержащих foo
-nПечатать номер строки (1-based, внутри файла)pgrep -n foo a.txt → 3:foo bar
-H / -hВсегда / никогда не печатать имя файлаpgrep -h foo a.txt b.txt → foo bar без префикса пути
-cПечатать только число совпавших строк на файлpgrep -c foo a.txt b.txt → a.txt:2, b.txt:0
-lПечатать только имена файлов с ≥1 совпадениемpgrep -l foo a.txt b.txt → a.txt
-j NЧисло рабочих потоков, N ≥ 1, по умолчанию hardware_concurrency()pgrep -j 4 -r foo src/ — 4 рабочих потока
-wСовпадение как целое словоpgrep -w cat a.txt найдёт a cat sat, но не concatenate
-xСовпадение покрывает строку целикомpgrep -x foo a.txt найдёт строку foo, но не foo bar
-qНичего не печатать, только код возвратаpgrep -q foo a.txt && echo found
--Конец опцийpgrep -- -foo a.txt — ищет подстроку -foo

2.2. Обход и чтение файлов

  • Без -r каталог в путях — ошибка по этому пути, остальные обрабатываются. pgrep foo a.txt src/ → a.txt обработан, pgrep: src: is a directory.
  • С -r — рекурсивный обход; символические ссылки не разыменовываются (защита от циклов).
  • Обход выполняется в главном потоке; рабочие потоки только читают файлы.
  • Каждый рабочий поток открывает и обрабатывает файл целиком самостоятельно. Файл не делится между потоками.
  • Файл без завершающего \n — последняя строка всё равно обрабатывается.
  • Пустой файл → 0 совпадений, без ошибок.
  • Нечитаемый файл (права, удалён между обходом и открытием) → сообщение в stderr, файл пропускается, остальные обрабатываются.

2.3. Правила совпадения

В каждом примере ниже — три блока рядом: содержимое файла (серый), запускаемая команда (тёмный) и что программа напечатает (зелёный).

Фиксированная подстрока. Ищется буквальная последовательность символов, без регулярных выражений. Каждая строка файла проверяется независимо.

Файл a.txt 
foo bar
baz
foo
Команда 
pgrep foo a.txt
Результат 
foo bar
foo

Строка baz не содержит foo и в вывод не попадает.

Пустой шаблон. "" совпадает с каждой строкой — выводятся все строки файла.

Файл a.txt 
foo
bar
Команда 
pgrep "" a.txt
Результат 
foo
bar

-v (инверсия). Печатает строки без совпадения. Применяется после матчинга, но до -c / -l — то есть -c считает уже инвертированные строки.

Файл a.txt 
foo
bar
foo
Команда 
pgrep -v foo a.txt
Результат 
bar
Тот же файл 
foo
bar
foo
Команда 
pgrep -vc foo a.txt
Результат 
a.txt:1

Несколько совпадений в строке не дублируют строку. Печатается строка целиком — один раз, сколько бы раз в ней ни встретился шаблон.

Файл a.txt 
foo foo foo
Команда 
pgrep foo a.txt
Результат 
foo foo foo

Одна строка — одна строка вывода, а не три.

-w — совпадение как целое слово. Символы непосредственно до и после совпадения не должны быть [A-Za-z0-9_]. Иначе говоря, cat внутри concatenate совпадением не считается.

Файл a.txt 
a cat sat
concatenate
cat
Команда 
pgrep -w cat a.txt
Результат 
a cat sat
cat

Строка concatenate отброшена: cat окружён буквами, а не границами слова.

-x — совпадение покрывает строку целиком. Совпадением считается только строка, целиком равная шаблону (с учётом -i, если он включён).

Файл a.txt 
foo
foo bar
Команда 
pgrep -x foo a.txt
Результат 
foo

Строка foo bar отброшена: подстрока foo в ней есть, но строка ей не равна.

2.4. Формат вывода

Формат строки: [путь:][номер:]содержимое\n. Для -c: [путь:]число\n (включая файлы с нулём совпадений). Для -l: путь\n без повторов.

pgrep -rn foo src/
src/a.c:3:foo bar
src/sub/b.c:17:foo baz

pgrep -c foo src/
src/a.c:2
src/sub/b.c:0

pgrep -l foo src/
src/a.c
src/sub/b.c
Порядок вывода не гарантируется. Строки не перемешиваются: каждая пишется целиком под мьютексом вывода. При -j 4 файлы могут идти не в алфавитном порядке — это нормально.

2.5. Последовательный режим

Просто цикл по всем найденным путям: открыть файл → построчно матчить → напечатать результат. Никаких потоков.

2.6. Параллельный режим

Главный поток обходит каталоги и складывает пути в общую std::queue<std::string>: один элемент — один файл. N рабочих потоков в цикле берут путь из очереди, обрабатывают файл и возвращаются за следующим. Кто освободился раньше — тот и берёт следующую задачу, поэтому быстрые и медленные файлы распределяются равномерно.

Когда очередь пуста, потоки завершаются. Главный поток дожидается их через join().

2.7. Итоговая статистика

После завершения программа печатает краткую сводку в stderr (или stdout — на Ваше усмотрение):

Processed: 120 files, 137 matches, 2 errors, 1.234 s

Всегда должно выполняться: success + errors = total.

3 Многопоточность

3.1. Общая картина

На рисунке 1 показано, как программа переходит от одного потока к нескольким и обратно. Сначала главный поток готовит задания — обходит каталоги и наполняет очередь путями. Затем создаются N рабочих потоков, каждый из которых в цикле забирает файл из общей очереди и обрабатывает его. Когда очередь пуста, все рабочие потоки завершаются, а главный дожидается их через join() и печатает итоговую сводку.

На рисунке 2 показан один шаг цикла, который выполняет каждый рабочий поток. Зелёным отмечены короткие операции над общими данными — они выполняются под мьютексом. Оранжевым — обработка файла, самая долгая часть: её поток выполняет без мьютекса, чтобы не блокировать остальные потоки.
