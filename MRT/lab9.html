1 Задание

Нужно написать консольную программу на C++17, которая:

  1. Спрашивает у пользователя входную и выходную директории, операцию и режим работы.
  2. Находит во входной директории все картинки (.png, .jpg, .jpeg, .bmp, .tga) через std::filesystem.
  3. Обрабатывает каждую картинку и сохраняет результат в выходную директорию.
  4. Умеет работать в двух режимах: последовательном и параллельном (N потоков через std::thread).
  5. Замеряет время обработки через std::chrono::steady_clock.
  6. Не падает из-за одного битого файла — считает его ошибкой и идёт дальше.
2 Что должна делать программа

2.1. Что умеет класс Image

Класс Image инкапсулирует работу с одним изображением: загрузку из файла, хранение пикселей, две операции и сохранение. Вам не нужно разбираться с пикселями — достаточно знать интерфейс:

class Image {
public:
    Image() = default;

    bool load(const std::string& filename);   // загрузить из файла
    bool save(const std::string& filename) const;  // сохранить в PNG

    void grayscale();                          // операция 1
    void invert();                             // операция 2

    int getWidth()  const noexcept;            // ширина после загрузки
    int getHeight() const noexcept;            // высота после загрузки

private:
    int width_  = 0;
    int height_ = 0;
    int channels_ = 4;                         // всегда RGBA
    std::vector<unsigned char> pixels_;
};

Что важно знать об этих методах:

  • load() читает файл и приводит изображение к формату RGBA (4 канала на пиксель) независимо от исходного формата. Возвращает true при успехе и false, если файл не открылся или оказался битым. При ошибке размеры обнуляются.
  • save() сохраняет изображение в формате PNG. Возвращает true при успехе и false, если сохранить не удалось (например, нет прав на запись).
  • grayscale() — операция 1. Для каждого пикселя считает яркость по формуле 0.299·R + 0.587·G + 0.114·B и записывает её в каналы R, G и B. Альфа-канал не меняется. Работает на месте, ничего не возвращает.
  • invert() — операция 2. Для каждого пикселя заменяет каждый из каналов R, G, B на 255 − C. Альфа-канал не меняется. Работает на месте.
  • getWidth() и getHeight() возвращают размеры загруженного изображения или 0, если изображение ещё не загружено или загрузка не удалась.
  • Никакие методы не бросают исключений — все ошибки сообщаются через возвращаемое значение bool или через нулевые размеры.

Операция «Grayscale + Invert» реализуется на стороне main.cpp последовательным вызовом grayscale(), затем invert().

Менять Image.h и Image.cpp нельзя. Все операции с многопоточностью, очередью и файловой системой должны находиться вне этого класса.

2.2. Диалог с пользователем

Программа последовательно спрашивает: входную директорию (откуда читать), выходную (куда сохранять), номер операции и режим работы. Между вопросами о директориях и операции она сканирует входной каталог и печатает, сколько картинок нашла. Если выбран параллельный режим, дополнительно спрашивается количество потоков — для последовательного этот вопрос пропускается.

Входная директория должна существовать, выходная создаётся автоматически, если её нет. Если картинок не найдено, программа сообщает об этом и завершается ещё до вопросов об операции и режиме. Любой некорректный ввод — сообщение об ошибке и завершение с кодом 1, без повторных попыток.

2.3. Как называть выходные файлы

Результат всегда сохраняется в PNG. Имя = полное исходное имя + .processed + .png:

photo.jpg    →  photo.jpg.processed.png
photo.png    →  photo.png.processed.png
cat.bmp      →  cat.bmp.processed.png

Так исходные файлы не перезаписываются, а имена не конфликтуют между собой (photo.jpg и photo.png дают разные выходные файлы).

2.4. Последовательный режим

Просто цикл по всем найденным файлам: загрузить → обработать → сохранить. Никаких потоков.

2.5. Параллельный режим

В параллельном режиме одну и ту же работу делят несколько потоков. Чтобы потоки не мешали друг другу и не обрабатывали один и тот же файл дважды, найденные картинки заранее складываются в общую очередь std::queue: один элемент — одна картинка. Поток в цикле берёт из очереди очередное задание, обрабатывает его, а затем возвращается за следующим. Кто освободился раньше — тот и берёт следующую картинку, поэтому быстрые и медленные файлы распределяются между потоками равномерно.

Когда очередь пуста, потоки один за другим завершаются. Главный поток дожидается их через join() и печатает сводку — до этого момента счётчики ещё могут меняться.

Ключевой момент — работа с очередью. Достать задание и проверить, что очередь не пуста, нужно под мьютексом, иначе два потока могут одновременно взять один и тот же элемент или сломать внутреннее состояние std::queue. А вот саму обработку картинки — загрузку, применение операции, сохранение — нужно делать уже без мьютекса: иначе потоки выстроятся в очередь и параллелизма не будет.

Главное правило: мьютекс защищает только короткие операции над общими данными (очередь, счётчики, вывод в консоль). Всё, что связано с обработкой картинки, выполняется вне мьютекса.

3 Многопоточность: что и чем защищать

3.1. Общая картина

На рисунке 1 показано, как программа переходит от одного потока к нескольким и обратно. Сначала главный поток готовит задания и наполняет ими очередь. Затем создаются N рабочих потоков, каждый из которых в цикле забирает задания из общей очереди и обрабатывает их. Когда очередь пуста, все рабочие потоки завершаются, а главный дожидается их через join() и печатает итоговую сводку.

На рисунке 2 показан один шаг цикла, который выполняет каждый рабочий поток. Зелёным отмечены короткие операции над общими данными — они выполняются под мьютексом. Оранжевым — обработка изображения, самая долгая часть: её поток выполняет без мьютекса, чтобы не блокировать остальные потоки.

3.2. Три мьютекса — три зоны

МьютексЧто защищаетКогда захватывать
queueMutexstd::queue<Task>Только на время empty() + front() + pop() — одним lock_guard.
statisticsMutexсчётчики success / failedТолько на время инкремента.
outputMutexвывод в std::cout из потоковТолько на время печати одной строки.

3.3. Что должен делать рабочий поток

Рабочий поток — это та часть программы, которую выполняет каждый std::thread, созданный в параллельном режиме. Как именно её оформить — отдельной функцией, лямбдой или функтором — студент решает сам. Важно, чтобы поведение соответствовало описанию ниже; рисунок 2 показывает то же самое в виде блок-схемы.

Поток работает в цикле и на каждой итерации делает четыре шага:

  1. Берёт задание. Под queueMutex проверяет, не пуста ли общая очередь. Если пуста — завершается. Если нет — извлекает одно задание и отпускает мьютекс.
  2. Обрабатывает изображение. Без мьютекса создаёт локальный объект Image, вызывает load() для входного пути. Если загрузка удалась — применяет выбранную операцию (grayscale(), invert() или обе подряд) и вызывает save() для выходного пути. Успех определяется как «load() вернул true и save() вернул true».
  3. Печатает результат. Под outputMutex выводит одну строку с номером потока и именем файла — успех или ошибка.
  4. Обновляет статистику. Под statisticsMutex увеличивает success или failed в зависимости от исхода обработки.

3.4. Возможные трудности

  • Держать queueMutex при обработке. Тогда все потоки выполняются по очереди — это не параллелизм.
  • Создавать один общий Image. Каждый поток должен создать свой локальный Image внутри обработки.
  • Забыть join(). Без него программа упадёт при выходе из main(), потому что потоки всё ещё живы.
  • Читать/писать счётчики без мьютекса. Приведёт к «потерянным» инкрементам и нарушению success + failed = total.

5 Эксперименты и отчёт

5.1. Что нужно замерить

  1. Подготовить ≥ 50 картинок разных размеров (маленькие, средние, крупные).
  2. Запустить последовательный режим — записать время T(1).
  3. Запустить параллельный с 2, 4, 8 потоками.
  4. Каждый запуск повторить 3 раза и взять среднее.
  5. Между запусками очищать выходную директорию.
