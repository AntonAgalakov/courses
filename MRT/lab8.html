1 Цель работы

Что уже есть

В лабораторной №7 был реализован CRUD через ODB: persist, load, update, query.

Что предстоит сделать

Расширить приложение операциями, которые выходят за рамки одиночного CRUD: транзакции с несколькими изменениями, каскадное удаление, поиск по нескольким полям, динамический query.

Что не меняется

Доменная модель — та же, что в лабе 7: Employee, Asset, Assignment. Схема БД не меняется. Вы пишете только методы сервисного слоя в src/service_lab8.cpp.

Обязательно: перед началом работы примените патч из раздела 2 к вашему проекту лабы 7. Без патча не будет ни кнопок в интерфейсе, ни заглушек в service_lab8.cpp.

4 Задание

Часть 1. Поиск с фильтрами ГОТОВО
Метод: Service::searchAssets
Зачем нужен: когда в базе сотни единиц, найти нужную по фильтру «категория + свободна» быстрее, чем листать таблицу глазами.
Где используется: вкладка «Техника» → кнопка «Поиск» → диалог SearchDialog. Пользователь выбирает категорию, отмечает «только свободные», вводит подстроку модели — видит отфильтрованную таблицу.
Почему готово: это эталон динамического query: начинаем с true_expr и добавляем условия через q = q && (...). Такой же паттерн пригодится в остальных методах. Разберите код.
Часть 2. Постраничный список ГОТОВО
Метод: Service::listAssetsPaged
Зачем нужен: если в базе 500 единиц, показывать их одной простынёй — тормоза и неудобно. Пагинация даёт по 20 строк на страницу.
Где используется: вкладка «Техника» → кнопки ◀ ▶ и надпись «Стр. N» над таблицей. Пользователь листает страницы, видит только 20 строк за раз.
Почему готово: это эталон комбинации «query + сортировка + срез + вложенный query». Показывает, как из результата query<Assignment> получить фотографа через load<Employee> в цикле (N+1).
Часть 3. История выдач единицы ГОТОВО
Метод: Service::assetHistory
Зачем нужен: если камеру поцарапали, надо понять, кто её брал последним — или сколько раз она вообще выдавалась, чтобы решить, не пора ли списать.
Где используется: вкладка «Техника» → выделить строку → кнопка «История» → диалог HistoryDialog. Пользователь видит список: фотограф, дата выдачи, дата возврата, статус.
Почему готово: эталон «query + load в цикле»: нашли все Assignment по assetId, для каждой загрузили Employee. На защите спросят: «Сколько запросов делает метод на 50 выдачах?» — ответ N+1 (51).
Часть 4. Что на руках у фотографа ГОТОВО
Метод: Service::employeeAssets
Зачем нужен: при увольнении фотографа нужно проверить, что у него на руках, чтобы принять технику. Или при аудите — кто что унёс со студии.
Где используется: вызова из UI нет — проверяется на защите через psql или отладочный вызов. Метод показывает, что Assignment — связующая сущность, и запросы можно строить с любой стороны.
Почему готово: обратная задача к assetHistory: query<Assignment> по employeeId с фильтром returnedAt.is_null(), для каждой — load<Asset>.
Часть 5. Копирование техники TODO
Метод: Service::duplicateAsset
Зачем нужен: студия купила 10 одинаковых камер. Заводить каждую с нуля — вводить 10 раз одну и ту же модель и категорию. Копирование: указал источник и новый инв. номер — готово.
Где используется: вкладка «Техника» → выделить строку → кнопка «Копировать» → диалог AssetDialog в режиме копирования. Модель и категория предзаполнены и заблокированы, поле «Инв. номер» пустое.
Контракт:
  • Вход: sourceId — существующая техника, newInv — новый инвентарный номер.
  • Успех: в БД одна новая запись, ничего не возвращается.
  • Ошибка: DomainError, если newInv уже занят, текст "Инвентарный номер <newInv> уже существует".
Критерии:
  1. Скопировать CAM-001 → CAM-002 — новая строка с моделью и категорией источника.
  2. Попытка CAM-001 → CAM-001 — fl_alert с текстом ошибки.
Часть 6. Массовая выдача TODO
Метод: Service::issueMultiple
Зачем нужен: фотографу на съёмку нужен комплект: камера + объектив + вспышка. Через обычную «Выдать» пришлось бы три раза открывать диалог.
Где используется: вкладка «Техника» → кнопка «Выдать несколько» → BulkIssueDialog. Пользователь выбирает фотографа, отмечает несколько единиц через Ctrl+Click, видит «Выбрано: N из M», жмёт «Выдать всё».
Контракт:
  • Вход: assetIds — список id техники, employeeId — фотограф.
  • Успех: все единицы «на съёмке», в assignments N новых записей с issuedAt = now, returnedAt = null.
  • Ошибки — DomainError: пустой assetIds — "Не выбрано ни одной единицы техники"; уволен фотограф — "Нельзя выдать уволенному фотографу"; единица занята — "Техника <inv> уже выдана".
  • При любой ошибке — ни одна единица не выдана.
Критерии:
  1. Выдать 3 единицы одной операцией — все три «На съёмке».
  2. 2 единицы свободны, 1 уже выдана → попытка выдать все 3 → fl_alert, ни одна из 3 не выдана (откат).
  3. Уволенный фотограф → fl_alert с текстом.
Часть 7. Смена фотографа TODO
Метод: Service::reassignAsset
Зачем нужен: камера у Иванова, но он заболел, а съёмка через час. Нужно передать Петрову, не возвращая в стойку — иначе камеру может перехватить кто-то третий.
Где используется: вкладка «Техника» → выделить выданную строку → кнопка «Сменить» → диалог ReassignDialog. Пользователь видит текущего фотографа и выбирает нового из списка.
Контракт:
  • Вход: assetId — выданная единица, newEmployeeId — новый фотограф.
  • Успех: старая выдача получила returnedAt = now, новая создана с issuedAt = now, asset.assigned остаётся true.
  • Ошибки — DomainError: техника не выдана — "Техника не выдана — используйте «Выдать»"; уволен новый фотограф — "Нельзя переназначить уволенному фотографу"; нет активной выдачи — "Нет активной выдачи"; тот же фотограф — "Техника уже у этого фотографа".
Критерии:
  1. CAM-001 у Иванова → «Сменить» на Петрова → CAM-001 у Петрова.
  2. В истории CAM-001 — 2 записи: закрытая у Иванова + открытая у Петрова.
  3. Попытка сменить на того же фотографа → fl_alert.
  4. Попытка сменить свободную единицу → fl_alert.
Часть 8. Удаление с историей TODO
Метод: Service::deleteAssetCascade
Зачем нужен: камеру списали — сломана без ремонта. Её надо убрать из учёта вместе с историей выдач, иначе в БД останутся висячие записи в assignments, и SELECT * FROM assignments будет ссылаться на несуществующий asset_id.
Где используется: вкладка «Техника» → выделить строку → кнопка «Удалить» → подтверждение через fl_choice. После удаления строка исчезает из таблицы.
Контракт:
  • Вход: assetId.
  • Успех: нет строки в assets, нет записей в assignments с этим assetId.
  • Ошибка: техника выдана — "Нельзя удалить выданную технику — сначала примите возврат".
Критерии:
  1. CAM-001 выдавалась 3 раза и сейчас свободна → «Удалить» → в БД нет ни строки в assets, ни записей в assignments с этим id.
  2. Попытка удалить выданную единицу → fl_alert.
