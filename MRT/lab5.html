2 Идея проекта

Идея проекта

Приложение «Пункт выдачи заказов» — рабочий инструмент оператора ПВЗ. Оператор принимает коробки от курьера, кладёт их в ячейки, выдаёт клиентам по телефону или коду заказа, отмечает отказы. Вечером смотрит отчёт за смену.

Графический интерфейс подготовлен. Основная работа выполняется в классе Database — единственном месте, где приложение общается с PostgreSQL.

Что важно понять в этой работе

Класс Database — это слой доступа к данным. Он не знает о FLTK и окнах. Он умеет только одно: превращать вызовы методов C++ в SQL-запросы к PostgreSQL и возвращать типизированный результат. Такой дизайн позволяет:

  • тестировать работу с БД отдельно от интерфейса;
  • менять UI, не трогая запросы;
  • сосредоточиться на libpqxx, а не на вёрстке.

Какие классы участвуют

Order

Простая структура данных. Описывает одну строку списка заказов для интерфейса.

Отвечает за: данные одного заказа.

Database

Класс доступа к PostgreSQL. Содержит pqxx::connection и реализует все операции.

Отвечает за: работу с базой данных.

MainWindow, AddOrderWindow, ReportWindow

Готовые окна FLTK. Вызывают методы Database и показывают результат.

Отвечает за: интерфейс.

Почему FLTK? Графический интерфейс здесь — не предмет изучения, а фон. Задача лабораторной — работа с libpqxx и PostgreSQL, поэтому для интерфейса выбрана самая простая и небольшая библиотека из доступных. FLTK — это лёгкий кроссплатформенный GUI-фреймворк на C++: собирается без зависимостей, весит меньше мегабайта, компилируется за секунды и требует минимум кода для окна с кнопками и таблицей. Альтернативы (Qt, GTK, wxWidgets) дают больше возможностей, но и тянут за собой зависимостb, долгую сборку и дополнительный слой абстракций, который в этой работе только отвлекал бы от сути.

5 Сборка и запуск

Зависимости

Для сборки проекта требуются:

  • компилятор C++ с поддержкой C++17;
  • CMake 3.16 или новее;
  • FLTK 1.3 — графический интерфейс;
  • libpqxx и libpq — работа с PostgreSQL;

Установка на Ubuntu / Debian:

sudo apt install build-essential cmake libfltk1.3-dev libpqxx-dev libpq-dev postgresql

Настройка PostgreSQL

Убедитесь, что сервер запущен:

sudo systemctl status postgresql

Создайте базу данных:

sudo -i -u postgres createdb pickup

Скопируйте schema.sql в /tmp (у пользователя postgres нет доступа к домашней папке) и примените схему:

cp ~/PVZ/schema.sql /tmp/schema.sql
head -3 /tmp/schema.sql
sudo -i -u postgres psql pickup -f /tmp/schema.sql

Создайте пользователя pickup_user и выдайте права:

sudo -i -u postgres psql pickup

Внутри psql:

CREATE USER pickup_user WITH PASSWORD 'pickup_pass';
GRANT ALL PRIVILEGES ON DATABASE pickup TO pickup_user;
GRANT ALL ON SCHEMA public TO pickup_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO pickup_user;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO pickup_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO pickup_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO pickup_user;
\q

Сборка проекта

cd ~/PVZ
mkdir build && cd build
cmake ..
make

Запуск

Строка подключения передаётся только через переменную окружения PICKUP_DB. В коде дефолтных значений нет — если переменная не задана, приложение выведет подсказку и завершится.

Два способа запустить:

Через скрипт (рекомендуется):

./run.sh

Вручную:

PICKUP_DB="host=localhost dbname=pickup user=pickup_user password=pickup_pass" ./pickup_point
Проверка подключения: если БД настроена верно, окно откроется и покажет статус «Готово». Если переменная не задана или БД недоступна — увидите сообщение в терминале и приложение завершится.

Схема БД (файл schema.sql)

DROP TABLE IF EXISTS orders;

CREATE TABLE orders (
    id              SERIAL PRIMARY KEY,
    order_code      VARCHAR(30) UNIQUE NOT NULL,
    phone           VARCHAR(20),
    parcel_article  VARCHAR(50),
    cell            VARCHAR(30),
    status          VARCHAR(20) NOT NULL DEFAULT 'ready',
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    issued_at       TIMESTAMP
);
Обратите внимание: поля phone и parcel_article взаимоисключающие. Если заказ принят по телефону, заполнено только phone; если по артикулу — только parcel_article. Поле cell — необязательное, может быть пустым. Все три поля в C++ приходят как пустые строки благодаря COALESCE.
7 Спецификация класса Database (src/db.cpp)

Назначение

Database — единственный класс, который общается с PostgreSQL. Все методы принимают простые аргументы (std::string, int) и возвращают простые значения (bool, int, std::vector<Order>, Report). Никаких типов libpqxx наружу не выходит.

Каждый метод реализуется через запросы к базе данных средствами библиотеки libpqxx. Никаких промежуточных контейнеров в памяти: класс только формирует SQL-запрос, выполняет его и преобразует ответ в объекты C++.

Данные класса

  • conn_ — объект pqxx::connection, хранит открытое соединение с БД.

Готовый код

В файле db.cpp уже реализованы:

  • Конструктор — открывает соединение и бросает исключение, если оно не открылось.
  • Функция looksLikePhone в анонимном namespace — определяет, что ввёл оператор: телефон или артикул. К работе с БД отношения не имеет.

Методы для реализации

Где реализовывать: все методы ниже пишутся в файле src/db.cpp. Каждый метод должен выполнять запросы к базе данных через объект транзакции pqxx::work. Заголовочный файл src/db.h, схему БД и файлы интерфейса изменять не нужно.
Выдать заказbool issueOrder(const std::string& code)РЕАЛИЗОВАТЬ
Вход: код заказа, например "PVZ-000001".
Предусловия: заказ с таким кодом существует.
Процесс:
  1. Выполнить запрос к базе данных: получить текущий статус заказа с указанным кодом.
  2. Если заказ не найден или его статус уже не ready — вернуть false.
  3. Иначе выполнить запрос к базе данных: перевести заказ в статус issued и записать дату выдачи.
Выход: true, если заказ выдан; false — иначе.
Постусловия: у заказа изменены status и issued_at. Поле cell не изменяется.
Подсказка: используйте параметризованный запрос, чтобы подставить код заказа. Не склеивайте SQL-строку вручную.
Отменить заказbool cancelOrder(const std::string& code)РЕАЛИЗОВАТЬ
Вход: код заказа.
Предусловия: заказ существует.
Процесс:
  1. Выполнить запрос к базе данных: получить текущий статус заказа с указанным кодом.
  2. Если заказ не найден или его статус уже не ready — вернуть false.
  3. Иначе выполнить запрос к базе данных: перевести заказ в статус cancelled.
Выход: true при успехе, false — иначе.
Постусловия: у заказа изменён только status; issued_at не заполняется.
Сводка по статусамReport buildReport()РЕАЛИЗОВАТЬ
Вход: нет.
Предусловия: нет.
Процесс:
  1. Для каждого из трёх статусов — ready, issued, cancelled — выполнить запрос к базе данных: посчитать, сколько заказов находится в этом статусе.
  2. Записать три получившихся числа в соответствующие поля структуры Report.
Выход: заполненная структура Report.
Постусловия: данные в БД не изменены.
Список заказов с поискомstd::vector<Order> listOrders(const std::string& filter)РЕАЛИЗОВАТЬ
Вход: строка поиска. Пустая строка — вернуть все заказы.
Предусловия: нет.
Процесс:
  1. Выполнить запрос к базе данных: получить список заказов со всеми полями структуры Order — идентификатор, код, телефон, артикул, ячейка, статус и дата создания.
  2. Поля phone, parcel_article и cell в базе могут быть пустыми — в этом случае заменить их пустой строкой, чтобы не получить ошибку при чтении.
  3. Если фильтр непустой — добавить в запрос условие: код, телефон или артикул содержат подстроку без учёта регистра.
  4. Отсортировать результат: сначала самые свежие заказы.
Выход: std::vector<Order>.
Постусловия: данные не изменены.
Подсказка: количество параметров в условии зависит от того, задан фильтр или нет. Для поиска по подстроке используйте txn.quote(...), чтобы экранировать значение.

Предусловия: нет.
Процесс:
  1. Выполнить запрос к базе данных: удалить все заказы со статусом issued или cancelled.

Принять заказstd::string addOrder(const std::string& contact, const std::string& cell)РЕАЛИЗОВАТЬ
Вход: contact — строка, которая может быть телефоном или артикулом. cell — код ячейки хранения, может быть пустой.
Предусловия: contact непустой, длина ≥ 5. cell не длиннее 30 символов.
Процесс:
  1. Определить по виду строки contact, что это — телефон или артикул.
  2. Если телефон — заполнить только поле phone, поле parcel_article оставить пустым. Если артикул — наоборот.
  3. Выполнить запрос к базе данных: вставить новую строку в таблицу заказов, передав телефон, артикул и ячейку. В качестве кода пока использовать временное значение. Запрос должен вернуть идентификатор, который база присвоила новой строке, — он понадобится на следующем шаге.
  4. Сформировать окончательный код заказа вида PVZ-000042: префикс PVZ- и номер из шести цифр, дополненный нулями слева. Номер взять из идентификатора, полученного на предыдущем шаге.
  5. Выполнить запрос к базе данных: обновить строку заказа — заменить временный код на сформированный.
  6. Зафиксировать изменения.
Выход: строка — сгенерированный код заказа, например "PVZ-000042".
Постусловия: в БД создан заказ со статусом ready, уникальным кодом и заполненным ровно одним из полей — phone или parcel_article. Поле cell содержит переданное значение (или пусто).
Исключения: ошибка БД при нарушении ограничений (например, дубликат кода).
Вопрос на защите: зачем нужен RETURNING id? Почему нельзя обойтись запросом «получить максимальный id»?

Ключевые понятия libpqxx

ПонятиеНазначение
pqxx::connectionОткрытое соединение с PostgreSQL. Создаётся один раз в конструкторе.
pqxx::workТранзакция. Создаётся в каждом методе. Автоматически откатывается при разрушении без commit().
txn.exec(sql)Выполнить SQL без параметров.
txn.exec_params(sql, args...)Выполнить SQL с параметрами $1, $2, .... Защищает от SQL-инъекций.
txn.quote(str)Экранировать строку для подстановки в SQL, если параметры не используются.
row[i].as<T>()Прочитать колонку i как тип T.
r.empty()Пустой ли результат SELECT.
r.affected_rows()Сколько строк затронуто UPDATE или DELETE.
txn.commit()Зафиксировать изменения. Без него всё откатится.
